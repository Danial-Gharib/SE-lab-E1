Repository Workflow

Branching Workflow Visualizer

This project follows a branch-based workflow where features are developed separately, reviewed through pull requests, merged into the development branch, and finally released through the protected main branch.

Feature Branches

feature/*

New website features, UI sections, and documentation changes are built in isolated branches.

  • feature/site-improvements
  • feature/github-pages-deploy
  • feature/project-shell
→
Integration Branch

dev

Completed feature branches are merged into dev first, so the team can review combined changes before production release.

→
Protected Branch

main

The main branch is protected and receives changes through pull requests only. This branch represents the deployable version of the project.

→
Deployment

GitHub Pages

After updates reach main, GitHub Actions builds and deploys the static frontend automatically to GitHub Pages.

Continuous Deployment

Deployment Pipeline Timeline

The project is deployed automatically after approved changes reach the protected main branch. GitHub Actions prepares the static files and publishes them through GitHub Pages.

01

Develop Locally

Team members create feature branches and implement changes locally using Git commands from the terminal.

02

Push Feature Branch

Completed commits are pushed to GitHub on a separate branch instead of being pushed directly to main.

03

Open Pull Request

The branch is reviewed through a pull request before being merged into dev or main.

04

Merge to Main

After review, changes are merged into the protected main branch through a pull request.

05

Run GitHub Actions

The deployment workflow uploads the static frontend files as a GitHub Pages artifact.

06

Publish on GitHub Pages

GitHub Pages serves the latest version of the static website from the successful workflow run.
